# Guidelines

How svnjn packages are written. Every rule here is enforced by a tool; the pages explain the why and show the pattern to use instead.

| Guide | Read it when |
|---|---|
| [Coding standards](coding-standards.md) | You start on a package, or a check fails and you want to know why. |
| [Data objects](data-objects.md) | You return data, accept input, or feel like returning an array. |
| [Errors](errors.md) | Something can fail. |
| [Testing](testing.md) | You write a test, a fake, or a test factory. |
| [Laravel](laravel.md) | The package has a Laravel integration. |
| [UI packages](ui.md) | The package ships Filament or dashboard screens. |
| [Writing docs](writing-docs.md) | You change the public API or write a usage page. |
| [Debugging](debugging.md) | A test, a type or the workbench misbehaves. |
| [Releasing](releasing.md) | You tag a version. |
| [Private packages](private-packages.md) | An app needs to install a private package. |
| [Going public](going-public.md) | A private package becomes open source. |
| [Local linking](local-linking.md) | You want to try a package inside a real app before releasing. |
